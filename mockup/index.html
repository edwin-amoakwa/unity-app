Merchant portal review

This review covers the current unity-app (Angular 21 on the Berry admin template) and what the mockup changes. The mockup keeps every feature and data field the app has today, and gives it the EcolinkPay brand.

What the app does today

  • Sign in with username and password, plus a password reset flow.
  • Registration: company name, contact person, industry, country, mobile, email, billing address, password, terms. Then a PIN sent by email to verify.
  • Dashboard: an account-pending banner, credit balance, SMS counts (total, sent, queued, failed, rejected), a date-range filter, a chart filtered by status, and the latest SMS.
  • Other pages: send SMS, SMS templates, contact groups, SMS records, sender IDs, add funds (top up), price list, API applications, users, notification settings, user and merchant profile, change password.

Issues found

Branding

The portal doesn't look like EcolinkPay

It's called "Ecolink-MMS" in the sidebar, "Ecolink MMS" on the sign-in page and uses a paper-plane icon as its logo. The website now links to it as "Merchant login", so it should carry the same logo, colours and font.

dashboard.component.html

The pending-account notice appears twice

Pending merchants see the yellow banner at the top and a second "Account Status: PENDING" card below the chart.

dashboard.component.html

A large hidden block is still in the page

The old dashboard sits inside @if (false), about 150 lines, along with commented-out code. It never renders and makes the file hard to work on.

dashboard.component.html

Colours and spacing are written inline

Ten inline style="" attributes and hard-coded colours (#1e9e57, #d64545, #d98a04) bypass the theme, so dark mode and future brand changes miss them.

Dashboard

Balance shows four decimal places

currency: "GHS" : "symbol" : "1.4-4" renders GH₵1,284.5000. Show the balance to two decimals and keep four only for the per-SMS unit price.

admin-layout

Menu icons repeat and the list is flat

SMS Templates and SMS Records share the same icon, as do Price List, User Profile and Merchant Profile. Twelve items in one list with no grouping are hard to scan.

admin-layout

Two menu items skip the permission check

SMS Templates and Price List are shown without allow(...), unlike every other item. Check whether that's intended.

Dashboard

The credit balance is the only money figure, and it's small

Merchants mostly need to know whether they can send. The mockup makes the balance the first card and converts it into an approximate number of SMS, using the existing smsBalance and unitPrice fields.

What the mockup changes

  • Brand: EcolinkPay logo, navy sidebar, green accents, Plus Jakarta Sans. Light and dark themes both use brand tokens.
  • Sign in and registration: brand panel on the left, explaining what the portal is for. "Keep me signed in" is new. Registration shows a two-step indicator, a +233 prefix on the mobile number, a password hint and a 6-box PIN entry. Confirm the PIN length the backend sends.
  • Navigation grouped into Messaging, Billing and Settings with plain names ("Top up balance", "Contact groups", "Team members"). Payments is in the menu marked "Soon", so the slot is ready when you add it.
  • Dashboard: one pending banner; the credit balance in its own strip at the top (how many SMS it covers, price per SMS, last top-up), kept apart from the SMS figures because it doesn't change with the date range; an "SMS activity" section where the date range controls the status cards and a line chart that switches between Sent, Failed and Rejected and has a table view; latest messages show recipients and per-status counts; a new Sender IDs card shows approval status with quick actions.
  • Palette switch (top bar): Brand is the proposed navy and green. Current teal repaints the same screens with the colours from the app's styles.css today, so you can compare. Either way, the app already keeps its colours in variables, so switching is mostly a matter of changing values in that one file.
  • Status colours are consistent everywhere (sent green, queued blue, failed red, rejected amber) and always come with an icon and a label.

New on the dashboard: needs backend data

  • The Sender IDs card needs the merchant's sender IDs and their status on the dashboard. The data already exists on the Sender IDs page.
  • "Last top-up" on the balance strip. The data is already on the Add Funds page (top-up history).
  • Recipient counts on the latest messages. The app shows per-status counts today, so total recipients is their sum.
  • "Resend PIN" with a countdown on the verify step.

How to build it in the Angular app

  1. Add the brand tokens (colours, radius, font) as CSS variables in styles.scss, with a dark set under the existing theme toggle.
  2. Create a PrimeNG preset with definePreset from @primeuix/themes, using Ecolink Navy as primary and Ecolink Green as accent, so selects, dialogs and tables match.
  3. Copy the logo SVGs and the Plus Jakarta Sans web font from the website's brand/ folder into src/assets.
  4. Rebuild the shared layout first (sidebar, topbar, user menu). Every page benefits at once.
  5. Then sign in, registration and dashboard, removing the hidden @if (false) block and the inline styles.
